# S1Lua Repository Guidance

S1Lua is a beginner-facing Lua scripting layer over S1API. The public Lua surface must stay smaller and simpler than S1API: expose stable IDs, plain Lua tables, strings, numbers, booleans, and callbacks; keep Unity, Schedule One, MelonLoader, Mono, and IL2CPP details internal.

## Source of truth

- `surface/s1lua.surface.json` owns the curated Lua API, documentation text, and S1API UID anchors.
- `tools/S1Lua.Generator` owns generated C#, LuaLS stubs, reference docs, and the compatibility snapshot.
- Files marked `<auto-generated>` must be regenerated, not hand-edited.
- A new S1API member is not automatically beginner-appropriate. Add it to the curated surface only when it supports a concrete beginner task with safe defaults.

## Commands

```powershell
./scripts/Generate.ps1
./scripts/Generate.ps1 -Check
dotnet test tests/S1Lua.Tests/S1Lua.Tests.csproj -c Release
dotnet build src/S1Lua.Runtime/S1Lua.Runtime.csproj -c MonoMelon -p:AutomateLocalDeployment=false
dotnet build src/S1Lua.Runtime/S1Lua.Runtime.csproj -c Il2CppMelon -p:AutomateLocalDeployment=false
./scripts/Package.ps1 -Configuration MonoMelon
./scripts/Package.ps1 -Configuration Il2CppMelon
```

## Safety and compatibility

- Never commit or package game assemblies, decompiled code, generated IL2CPP wrappers, saves, logs, or exported Unity assets.
- Keep each Lua mod in its own MoonSharp `Script` and do not register arbitrary CLR userdata.
- Keep file access confined to the mod's own directory.
- Preserve the same Lua surface and behavior in Mono and IL2CPP.
- Validate both runtime configurations separately before claiming cross-runtime compatibility.
- Pin interpreter and API versions; update them through a reviewed generator drift report.
